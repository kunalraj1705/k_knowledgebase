## 1. Kubernetes Core Concepts

## 2. Pods, Deployments and ReplicaSets
A Pod is the smallest deployable unit. Pod names are generated by Kubernetes.

Typical Deployment naming:

`Deployment → ReplicaSet → Pod`

Example:

`krb-enterprise-796bd45c4-5n2px`

Individual Pod names should not be hard-coded.

The container name is separately defined in:

`spec.template.spec.containers[].name`

For KRB Enterprise:

`krb-enterprise`

- Name: `postgres`
- Namespace: `uat-core`
- Replicas: 1

Architecture decision: PostgreSQL lifecycle is managed separately from application CI/CD. GitHub Actions does not start, stop, scale, or modify PostgreSQL.

## 5. Probes
Covered:
- Readiness: controls whether a Pod receives traffic.
- Liveness: determines whether a container should be restarted.
- Startup: protects slow-starting applications during initialization.

For deployment verification, Kubernetes readiness is the primary Pod-level health mechanism.

## 6. Rolling Updates
KRB Enterprise uses `RollingUpdate`.

Deployment process:
1. New ReplicaSet is created.
2. New Pods start.
3. New Pods become Ready.
4. Traffic moves to Ready Pods.
5. Old Pods are removed according to the rollout strategy.

Image update:

```bash
kubectl set image deployment/krb-enterprise   krb-enterprise="$IMAGE"   -n uat-core
```

Rollout verification:

```bash
kubectl rollout status deployment/krb-enterprise   -n uat-core   --timeout=180s
```

## 7. HPA, PDB and Resources
HPA:
- Minimum: 2
- Maximum: 5
- CPU target: 60%

KRB Enterprise resources:
- CPU request: `500m`
- Memory request: `512Mi`
- CPU limit: `1`

HPA scales based on configured resource utilization, not simply on HTTP health-check count.

## 14. Replica Behavior
CI/CD should not blindly force the application to two replicas.

Desired behavior:
- If already running with N replicas, preserve N.
- If scaled to zero, deployment can bring it back to its baseline running state.
- PostgreSQL remains independently managed.

## 15. Image Verification
Deployment image:

```bash
kubectl get deployment krb-enterprise   -n uat-core   -o jsonpath='{.spec.template.spec.containers[?(@.name=="krb-enterprise")].image}'
```

Pod images:

```bash
kubectl get pods   -n uat-core   -l app=krb-enterprise   -o custom-columns='POD:.metadata.name,IMAGE:.spec.containers[0].image'
```

Containerd image list:

```bash
sudo ctr -n k8s.io images list
```

`crictl` is not installed on the node.

## 16. Troubleshooting Lessons
- A Deployment can exist with zero Pods when replicas are zero.
- `kubectl set image` changes the Pod template; it does not start a Deployment scaled to zero.
- PostgreSQL being Running does not mean KRB Enterprise is running.
- Ingress may briefly return `502` while upstreams transition.
- Kubernetes rollout/readiness should gate external health verification.
- Pod names are ephemeral; use labels, Deployments, ReplicaSets and revisions instead.
