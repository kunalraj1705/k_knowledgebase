# KRB Academy — AWS EC2 Notes
## Session: EC2 Fundamentals, Networking & Lifecycle
### Date: 2026-09-22

## 1. EC2 — Elastic Compute Cloud
EC2 provides virtual compute servers in AWS. An EC2 instance provides CPU, memory, networking, and storage through services such as EBS.

Important:
> An EC2 instance lives inside a VPC and a subnet.

## 2. AMI — Amazon Machine Image
An AMI is a template/image used to launch EC2 instances. It can contain the operating system, software, application dependencies, and configuration.

```text
                 AMI
              Blueprint
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      EC2-A     EC2-B     EC2-C
```

A custom AMI avoids manually installing the same software on every new instance and is useful for scaling.

Important:
> An AMI is not the complete EC2 instance configuration. Instance type, subnet, Security Group, and some networking settings are selected when launching the instance.

## 3. EC2 Networking

### Private IP
Assigned from the subnet and used for communication within the VPC/private network.

Example:

```text
VPC:            10.0.0.0/16
Private Subnet: 10.0.1.0/24
EC2:            10.0.1.10
```

### Public IP
Provides Internet-facing connectivity when routing and security configuration permit it.

Important:
> A public IP does not automatically make an instance accessible; routing and Security Groups also control reachability.

### Elastic IP
A static public IPv4 address allocated to the AWS account. For KRB Enterprise, the backend does not need a public IP because the Load Balancer/DNS provide the stable application entry point.

### ENI
Elastic Network Interface is the virtual network interface attached to an EC2 instance.

```text
EC2
└── ENI
    ├── Private IP
    ├── Security Groups
    └── MAC address
```

Physical analogy:
> Physical machine → Network Card; EC2 → ENI.

## 4. DNS
DNS resolves a hostname to a network endpoint.

```text
api.krbenterprise.com
        ↓
       DNS
        ↓
Load Balancer
```

Important distinction:
> DNS identifies the entry point; the Load Balancer distributes application traffic to backend targets.

## 5. SSH and Systems Manager
Linux EC2 instances can use SSH over TCP port 22.

Prefer allowing SSH only from an appropriate administrator source rather than `0.0.0.0/0`.

For private backend instances, AWS Systems Manager can provide management access without directly exposing SSH to the public Internet.

```text
Administrator
      ↓
AWS Systems Manager
      ↓
Private EC2
```

## 6. EBS — Elastic Block Store
EBS provides block storage for EC2.

```text
EC2
 │
 └── EBS Volume
       └── Data
```

EC2 compute and EBS storage are separate concepts.

When EC2 is stopped, EBS data can remain persisted.

## 7. Stop vs Terminate

### Stop
Releases the EC2 compute resources while allowing the instance to be started again.

```text
Running → Stopping → Stopped → Starting → Running
```

EBS volumes can remain.

### Terminate
Permanently removes the EC2 instance.

```text
Running → Terminating → Terminated
```

Whether attached EBS volumes are deleted depends on `DeleteOnTermination`.

Mental model:

```text
STOP
EC2 → Stopped
EBS → can remain

TERMINATE
EC2 → removed
EBS → depends on configuration
```

## 8. EC2 IP Behavior
After Stop → Start:
- Private IP generally remains associated with the ENI.
- A normal public IPv4 address can change.

After Terminate → recreate:
- The new EC2 may receive a different private IP.

For a stable public application endpoint, prefer Load Balancer/DNS rather than relying on an individual EC2 public IP.

## 9. EBS and Availability Zones
An EBS volume is tied to a specific Availability Zone.

```text
AZ-A
├── EC2-A
└── EBS-A
```

The same EBS volume cannot simply be attached directly to an EC2 in another AZ.

Cross-AZ resilience requires appropriate backup/replication and architecture.

## 10. EBS Snapshot
An EBS Snapshot is a point-in-time backup/copy mechanism for an EBS volume.

```text
EBS Volume
     ↓
EBS Snapshot
     ↓
New EBS Volume
```

Do not confuse:
- EBS → primary block storage
- EBS Snapshot → backup/copy mechanism

## 11. EC2 Lifecycle
Important states:

```text
Pending
   ↓
Running
   ↓
Stopping
   ↓
Stopped
   ↓
Starting
   ↓
Running

Running
   ↓
Terminating
   ↓
Terminated
```

### Pending
`Pending` means AWS is launching/preparing the EC2 instance, including compute, storage, networking, and image configuration.

```text
Pending → Running
```

Once Running, the instance is ready to operate normally.

## 12. KRB Enterprise AWS Architecture

```text
                         Internet
                            │
                            ▼
                           DNS
                            │
                            ▼
                    Load Balancer
                    Public Subnets
                            │
                 ┌──────────┴──────────┐
                 │                     │
                AZ-A                  AZ-B
                 │                     │
          Private Subnet A      Private Subnet B
                 │                     │
               EC2-A                  EC2-B
                 │                     │
                 └──────────┬──────────┘
                            │
                       PostgreSQL
```

Each EC2:

```text
EC2
├── Instance Type
├── AMI
├── ENI
│   ├── Private IP
│   └── Security Groups
└── EBS
```

Management:

```text
Administrator
      ↓
AWS Systems Manager
      ↓
Private EC2
```

## 13. Cloud Architecture Principle

> Do not make an EC2 instance the source of truth for application state.

Prefer:

```text
Compute
→ disposable/recreatable

Application image
→ reproducible

Persistent storage
→ separately managed

Database
→ separately managed
```

This makes scaling and failure recovery easier.
